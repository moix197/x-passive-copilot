## Tone
- Plain, calm, confident, short sentences. Concrete nouns over adjectives.
- Say what a user can now see or do. Lead with the benefit, not the implementation.
- Match the product's own empty-state and UI copy.

## Hard rules
- No layout descriptions as copy.
- Never imply a native or mobile app unless one exists. For phones say "the site works on any screen".
- No latency or speed claims, no "fresher/faster/real-time" promises.
- No invented numbers. Use a figure only if it is in `brief.md`.
- No hype words or claims that read as advice or guarantees.
- Calculation formulas are internal: show results and features, never the math.
- Never name private infra: TODO (DB/hosting providers, API keys, quotas, budgets).
- Everything must trace to `brief.md`; anything under its "Don't say" is out.
